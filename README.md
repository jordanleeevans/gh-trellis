# trellis

trellis is a terminal UI for [`gh stack`](https://github.com/github/gh-stack),
the GitHub CLI extension for stacked pull requests. In the style of LazyGit, it
lets you browse stacks, layers and diffs, and run the common `gh stack`
operations (checkout, add layer, submit, sync, rebase, merge, unstack) from
keyboard shortcuts instead of remembering flags.

## Requirements

| Tool | Minimum | Install |
| --- | --- | --- |
| git | 2.20.0 | https://git-scm.com/downloads |
| gh (GitHub CLI) | 2.90.0 | https://cli.github.com |
| gh-stack extension | 0.1.0 (only checked when `gh extension list` prints a version) | `gh extension install github/gh-stack` |
| gh authentication | logged in | `gh auth login` |

trellis checks all four at startup. If any fail, it prints what is missing
and how to fix it, then exits with status 1. Building from source also needs a
Rust toolchain that supports edition 2024 (Rust 1.85 or newer).

## Install

trellis is a [GitHub CLI extension](https://docs.github.com/en/github-cli/github-cli/using-github-cli-extensions),
installed the same way as gh-stack:

```sh
gh extension install jordanleeevans/gh-trellis
gh trellis                          # run it
gh extension upgrade trellis        # later, to update
```

This downloads a prebuilt binary for macOS (Apple silicon and Intel), Linux
(x86_64 and arm64) or Windows (x86_64) from the latest
[release](https://github.com/jordanleeevans/gh-trellis/releases). Until the
first release is published, install from source instead.

With cargo, once the crate is published to crates.io:

```sh
cargo install gh-trellis
```

From source (Rust 1.85 or newer):

```sh
cargo install --git https://github.com/jordanleeevans/gh-trellis
```

Both cargo installs put a `gh-trellis` binary in `~/.cargo/bin`. Run it
directly as `gh-trellis`; `gh trellis` only finds extensions installed with
`gh extension install`.

## Quickstart

trellis shows the stacks that `gh stack` tracks in the current repository, so
you need a repository with a stack. If you have one, skip to step 2.

1. Create a stack with gh-stack (from the
   [gh-stack quick start](https://github.com/github/gh-stack#quick-start)):

   ```sh
   gh stack init                 # start a stack; creates and checks out the first branch
   # ... commit on the first branch ...
   gh stack add api-endpoints    # add a branch on top
   # ... commit ...
   gh stack push                 # push all branches
   ```

   Submitting (`gh stack submit`, or `s` in trellis) is only needed to open
   the pull requests; layers without a PR still show their commits.

2. Run trellis from inside the repository:

   ```sh
   gh trellis        # or gh-trellis, if you installed with cargo
   ```

If the repository has no stacks, the navigator says "No stacks found in this
repository."

### The screen

- **Navigator** (left): every stack, with its layers listed under it.
- **Details** (right): the selected layer's pull request summary.
- **Changed files** and **diff**: press `d` to switch the right side to the
  layer's changed files and diff, and `d` again to go back.
- **Footer**: hints for the focused panel. It always includes `? help` and
  `q quit`.

Move with `j`/`k` (or the arrow keys), press `Tab` to move focus between
panels, and `Enter` to drill in. `o` opens the selected layer's PR in your
browser. Press `?` at any time for every key binding.

On terminals narrower than 90 columns, trellis shows one column at a time
(the header says `1/2 navigator` or `2/2 details`) and `Tab` switches between
them.

## Key bindings

These are the defaults. The `?` overlay shows the bindings currently in
effect, including your overrides and the current state of the toggles.
Bindings can be changed in the config file; see [docs/config.md](docs/config.md).

### Navigation

| Keys | Action |
| --- | --- |
| `j` / `Down` | Move down |
| `k` / `Up` | Move up |
| `Tab` | Next panel |
| `Shift+Tab` | Previous panel |
| `Enter` / `Space` | Open / drill in |
| `q` / `Esc` | Back / quit (asks to confirm) |
| `r` | Refresh |

### Stack

| Keys | Action |
| --- | --- |
| `c` | Check out the selected stack or layer |
| `a` | Add a layer (prompts for a branch name, then an optional commit message) |
| `s` | Submit the stack |
| `t` | Toggle `submit --auto` |
| `p` | Toggle `submit --open` |
| `S` | Sync the stack (shows a plan and asks to confirm) |
| `P` | Toggle `sync --prune` |
| `M` | Merge the stack (irreversible) |
| `m` | Cycle the merge method: merge, squash, rebase |
| `R` | Rebase the stack |
| `u` | Rebase from the checked-out layer up |
| `D` | Unstack, local tracking only |
| `U` | Unstack on GitHub |
| `W` | Restructure the stack in `gh stack modify` (drop, fold, reorder, rename; asks to confirm) |

### Layer

| Keys | Action |
| --- | --- |
| `o` / `O` | Open the PR in the browser |
| `d` | Toggle the diff view |

### Diff

| Keys | Action |
| --- | --- |
| `PageDown` | Page down |
| `PageUp` / `Backspace` | Page up |
| `Ctrl+d` | Half page down |
| `Ctrl+u` | Half page up |
| `gg` | Top |
| `G` | Bottom |

### General

| Keys | Action |
| --- | --- |
| `x` | Dismiss an error or notice |
| `?` | Toggle the help overlay |

### Rebase conflicts

When a rebase stops on a conflict, trellis shows a conflict view listing the
conflicted files instead of the browser. It uses `j`/`k` to move between files
and `r` to reload the list, plus:

| Keys | Action |
| --- | --- |
| `e` | Open the file in `$EDITOR` (falls back to `vi`) |
| `+` | Mark the file resolved (`git add`) |
| `C` | Continue the rebase |
| `A` | Abort the rebase and restore the branches (asks to confirm) |
| `q` / `Esc` | Quit; the rebase stays stopped |

### Confirmations

- **Type `yes` to confirm** (case-insensitive; Enter accepts, Esc cancels):
  merge (`M`) and unstack on GitHub (`U`).
- **Enter to confirm, Esc to cancel**: quit, sync, rebase, restructure
  (`W`), abort rebase and local unstack.
- **No confirmation**: submit (`s`), checkout (`c`) and add layer (`a`, which
  has its own prompt you can cancel with Esc).

## Configuration

trellis reads an optional TOML file (`~/.config/trellis/config.toml` on Linux
and macOS, or `$XDG_CONFIG_HOME/trellis/config.toml`; `TRELLIS_CONFIG`
overrides the path). It controls the refresh interval, default remote, Nerd
Font glyphs, theme and key bindings. All fields are optional. See
[docs/config.md](docs/config.md).
